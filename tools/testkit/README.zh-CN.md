# D 便携测试包使用说明

这是独立的离线后端验证工具，使用D的正式推理后端。它不会安装或替换普通D，不代表所有大模型已验收，也不自动操作D的界面。不要把整个测试包分享给别人：其中模型仍有各自的使用条款。可以带回并分享经过脱敏的结果包。

## 出发前

1. 带上整个D-TestKit文件夹所在的SSD和合适的数据线，不要只复制Start.command。七组固定模型共约42.14GB，运行环境另占少量空间；SSD还应保留至少10GB结果空间。
2. 需要Apple Silicon Mac，测试包最低系统要求macOS 26.2。实际新机器兼容性由现场预检与运行确认。
3. 本包包含固定模型和运行环境；现场无需下载模型、安装Python、登录GitHub或登录开发者账号。有Xcode会记录其可用信息，但不依赖现场重新构建。
4. 模型文件不可修改或改名；不要修改包内程序。结果写在Results，不能写回Models或Inputs。
5. 请先征得店员同意在展示机运行自带测试程序。不要为了测试关闭系统安全功能，不要输入个人账号或复制签名私钥。

## 在展示机开始

1. 连接SSD，在访达打开D-TestKit文件夹。
2. 确认没有需要保护的正在运行的AI生成任务；本工具不会替你关闭其他应用。
3. 双击Start.command，按屏幕菜单选择测试组。首次打开程序或外盘若出现系统提示，请只在店员允许且提示内容明确时处理。
4. 菜单输入数字，再输入大写`RUN`确认开始。先选`1`（quick快速检查），确认文字、图像、音频基础链路。再按时间选择`2`（common共同对照）、`3`（capacity容量扩展）或`4`（reliability重复、取消和音频编辑）。每组结束后按回车关闭窗口；需要下一组时重新双击Start.command。
5. 预检校验模型会读取大量数据，等待时不要拔盘。内存不足、缺失文件或系统不支持会明确记录，不会悄悄换成更小配置。
6. 模型运行期间不要同时启动另一份测试或其他重型AI任务。每个用例完成后结果立即保存。

## 四组测试

| ID | 用途 | 范围 |
|---|---|---|
| quick | 出发前和现场首先运行 | 0.5B文字、512图像、small 6秒音频 |
| common | 同参数比较两台Mac | 7B文字、1024图像、small 30秒音频 |
| capacity | 当前16GiB机器未覆盖的大配置 | 32B与长输入、1536/2048图像、medium及长音频 |
| reliability | 取消、恢复、编辑和重复加载 | 1.5B文字重复/取消，small生成/参考变体/重绘/取消 |

大配置不是必须全部运行。36GB机器可能按既有预算拒绝32B；这是一条有效边界记录，不是要求你修改内存保护。profile名字中的8K/16K表示配置输入上限，实际token数量以模型输出记录为准。

## 停止与故障

- 需要停止时在测试终端按Control-C一次，等待取消、子进程退出和状态保存；不要直接拔掉SSD。
- 工具会记录超时、失败或强制结束。取消实验只有按约定正常结束才能记为通过。
- 取消实验按固定秒数发送请求；特别快的机器可能先完成生成，此时该项不能证明取消功能，会保留为未通过并注明终态不匹配。保留报告即可，不需修改参数或重复尝试。
- 若系统阻止程序启动，请记下完整提示或拍照，并保留现状。不要执行网上关闭Gatekeeper、删隔离属性或sudo修改权限的命令。
- 若提示Xcode未就绪，本包不自动安装/初始化它；预编译后端能否继续由工具检测决定。
- 若磁盘空间不足或SSD失联，停止继续测试。重新连接后检查未完成结果，不把它们算作通过。
- 用例失败可保留证据继续无依赖的用例；不要修改断言、输出文件或profile把失败改成成功。

## 带回什么

结果位于本包Results下，每次运行有独立ID。保留整个Results目录；工具提供的summary.json/summary.html和ZIP是可移交结果，private目录的原始日志不默认进入ZIP。生成文字、图片、音频、实际参数和耗时/内存信息都属于结果；模型权重不会重复打包。

离店前确认当前任务已经结束，再通过访达正常推出SSD。回来后把SSD接回本机，告诉Lead测试了哪台机器、是否有系统阻止提示。无需手工整理日志或把模型上传云端。

## 如何理解报告

执行完成、媒体结构正确和创作质量满意是不同结论。人耳/看图/文字内容检查会保留为待人工判断，不能仅凭一个绿色状态宣称质量最好。MLX分配峰值不是整机内存；RSS采样也不等于去重后的CPU/GPU物理占用。首次完整校验会影响文件缓存，报告不能据此声称磁盘完全冷启动。

本工具验证后端能力；工作台界面、签名跨机器长期有效性、麦克风和音乐理论/精确谱面服从不由这些测试证明。不要在展示机上做完整GUI自动验收或录音。

## 本次制作验收记录

随包的`Acceptance.json`记录本次制作的代码版本、小配置实测及移位检查；其中未执行的项目不算通过。现场结果另存`Results`，不会覆盖制作证据。另一台Mac上的运行和大配置实测必须由现场结果确认。
