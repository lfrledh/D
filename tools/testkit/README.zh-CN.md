# D 便携测试包使用说明

这是独立的离线后端验证工具，使用D的正式推理后端。它不会安装或替换普通D，不代表所有大模型已验收，也不自动操作D的界面。不要把整个测试包分享给别人：其中模型仍有各自的使用条款。可以带回并分享经过脱敏的结果包。

## 出发前

1. 带上整个D-TestKit文件夹所在的SSD和合适的数据线，不要只复制Start.command。八组固定模型共约83.05GB，运行环境另占少量空间；SSD还应保留至少20GB结果空间。
2. 需要Apple Silicon Mac，测试包最低系统要求macOS 26.2。实际新机器兼容性由现场预检与运行确认。
3. 本包包含固定模型和运行环境；现场无需下载模型、安装Python、登录GitHub或登录开发者账号。有Xcode会记录其可用信息，但不依赖现场重新构建。
4. 模型文件不可修改或改名；不要修改包内程序。结果写在Results，不能写回Models或Inputs。
5. 请先征得店员同意在展示机运行自带测试程序。不要为了测试关闭系统安全功能，不要输入个人账号或复制签名私钥。

## 在展示机开始

1. 连接SSD，在访达打开D-TestKit文件夹。
2. 确认没有需要保护的正在运行的AI生成任务；本工具不会替你关闭其他应用。
3. 双击Start.command，按屏幕菜单选择测试组。首次打开程序或外盘若出现系统提示，请只在店员允许且提示内容明确时处理。
4. 菜单输入数字，再输入大写`RUN`确认开始。先选`1`（quick快速检查），确认文字、图像、音频基础链路。96GB及以上优先选`6`（boundary96），然后选`7`（boundary72，96/128/192GB的72B实际容量试探）；64GB或时间较短可选`5`（showroom）。再按时间选择`2`（common共同对照）、`3`（capacity容量扩展）或`4`（reliability重复、取消和音频编辑）。每组结束后按回车关闭窗口；需要下一组时重新双击Start.command。
5. 预检校验模型会读取大量数据，等待时不要拔盘。资源估算会保留为参考；本包测试组启用实际容量试探，不因超出推荐预算自动跳过。缺失文件、不支持参数/系统或实际加载/执行失败会明确记录，不会悄悄换成更小配置。
6. 模型运行期间不要同时启动另一份测试或其他重型AI任务。每个用例完成后结果立即保存。

## 七组测试

| ID | 用途 | 范围 |
|---|---|---|
| quick | 出发前和现场首先运行 | 0.5B文字、512图像、small 6秒音频 |
| common | 同参数比较两台Mac | 7B文字、1024图像、small 30秒音频 |
| capacity | 当前16GiB机器未覆盖的大配置 | 32B与长输入、1536/2048图像、medium及长音频 |
| reliability | 取消、恢复、编辑和重复加载 | 1.5B文字重复/取消，small生成/参考变体/重绘/取消 |
| showroom | 六项均超出当前M4/16GiB的安全预算 | 32B短输入/8K上限/16K上限，1536与2048图像，medium 120秒音频 |
| boundary96 | 96GB及以上优先；检查长输入、重复释放、取消和当前媒体上界 | 32B实际26,455 token输入两轮/取消/短输入恢复，2048图像两轮，medium 380秒音频 |
| boundary72 | 同一组在96/128/192GB实际尝试，比较结果及失败边界 | 72B短输入两轮、实际26,455 token输入两轮、长输入取消、独立新进程短输入 |

大配置不是必须全部运行。profile名字中的8K/16K表示配置输入上限，实际token数量以模型输出记录为准。showroom与capacity有重叠，不必为了数量重复运行两组。

## 测试用的容量试探模式

本包七个组都显式使用`probe`。工具先校验文件与请求，再记录正式后端的估算、真实物理内存和保守推荐预算；估算超推荐时仍会实际尝试加载/推理。为进入既有正式运行时，测试工具单独提高本次**准入阈值**到不低于估算值，并把推荐值与执行值分别保存。这不是伪装机器内存，也不是修改macOS/交换空间/系统权限或生产App默认策略；准入阈值与MLX allocator选项都不能当作进程RSS硬上限。

实际加载/生成报错、异常退出、缺失或损坏报告、超时、无效输出均保留为失败。试探失败后本组停止，余项标为未启动，不自动重试。有效的取消实验仍可通过并继续。若操作系统直接终止子进程，父监控记录实际退出/信号；不能只凭SIGKILL断言OOM。若连监控本身也被系统终止，已有未完成记录供重新汇总，不能承诺当场弹出完整诊断。请保留Results，不自行删除失败证据。

测试组正常完成返回0；生成了报告但试探失败/不完整返回1。旧版未声明policy的profile仍是guarded兼容模式，summarize只表示报告成功生成。结构校验与创作质量判断继续分开。

## 96／128／192 GB 现场顺序

先运行1，再运行6、7。若时间有限，在完成6的文字部分后可按Control-C停止余下用例，带回已完成证据；大图与380秒音频是额外高负载检查。每个用例有10～40分钟的停止上限，这是保护上限，不是预计耗时。整组上限可超过两小时，不要为了跑全耽误离店；无需把所有组都跑一遍。

| 机器内存档 | 原保守推荐预算（仅参考） | 72B短输入／长输入 |
|---|---|---|
| 96 GiB | 72 GiB | 两者均实际尝试，不按估算提前拒绝 |
| 128 GiB | 96 GiB | 两者均实际尝试 |
| 192 GiB或以上 | 至少144 GiB | 两者均实际尝试，可比较重复运行与长输入表现 |

GB档位按系统报告的物理字节换算GiB。72B短输入保守估算约78.1GiB、长输入约96.7GiB，包含权重双份、KV缓存和工作区；它们不是实际内存需求或最低硬件承诺。现场用实际加载结果、峰值、耗时、swap变化来校准。全部用例串行；不为了占满内存并发多个模型。本机16GiB制作验收只运行安全小配置，72B留给展示机，不能把制作过程写成已完成大模型实测。

新增长输入已用同tokenizer/模板的小模型校准为26,455 tokens；现场仍检查实际promptTokens。输入上限为32768，输出最多256 tokens，并不要求模型输出满256；EOS提前结束正常。这是容量/生命周期用例，重复合成段落不是专业写作质量或长文检索评分。本后端未接入YaRN，不把模型卡宣称的128K当成当前支持。

重复用例是在**同一个CLI进程中**跑两轮，保存每轮MLX加载/清理数据；它不等于模型常驻。取消实验后的短输入是**新进程独立检查**，用于前项取消通过后的独立进程验证；若前项试探失败，本组会停止，后项不会自动启动。只有同一attempt中前项实际取消通过且后项成功，二者合起来才证明取消后的新进程恢复；单独的后项成功不能证明取消发生，更不能声称证明同Runtime排队交接。2秒取消可能发生在权重加载或计算边界，现场依据实际阶段记录，不能保证恰在长输入预填充中。380秒音频输出为44.1kHz双声道float32 WAV，约134MB；不降低精度、不转成短音频冒充通过。2048图像和medium时长上界不需要占满96GB，仍有独立验证价值。

72B仅获准本用户的离线开发测试。固定权重revision见Manifests/text72.json，[Qwen协议](https://huggingface.co/Qwen/Qwen2.5-72B-Instruct/blob/main/LICENSE)及来源副本见Manifests/Qwen-72B-LICENSE.txt、Qwen-72B-Notice.txt；它与其他型号许可不能混为一谈。原生CLI第三方许可副本见Manifests/Native-THIRD-PARTY-NOTICES.txt。不要公开上传模型。

## 停止与故障

- 需要停止时在测试终端按Control-C一次，等待取消、子进程退出和状态保存；不要直接拔掉SSD。
- 工具会记录超时、失败或强制结束。取消实验只有按约定正常结束才能记为通过。
- 取消实验按固定秒数发送请求；特别快的机器可能先完成生成，此时该项不能证明取消功能，会保留为未通过并注明终态不匹配。保留报告即可，不需修改参数或重复尝试。
- 若系统阻止程序启动，请记下完整提示或拍照，并保留现状。不要执行网上关闭Gatekeeper、删隔离属性或sudo修改权限的命令。
- 若提示Xcode未就绪，本包不自动安装/初始化它；预编译后端能否继续由工具检测决定。
- 若磁盘空间不足或SSD失联，停止继续测试。重新连接后检查未完成结果，不把它们算作通过。
- 试探失败后当前组会停止。保留证据，确认机器仍适合继续后，可另开一组无依赖测试；不要修改断言、输出文件或profile把失败改成成功。

## 带回什么

结果位于本包Results下，每次运行有独立ID。保留整个Results目录；工具提供的summary.json/summary.html和ZIP是可移交结果，private目录的原始日志不默认进入ZIP。生成文字、图片、音频、实际参数和耗时/内存信息都属于结果；模型权重不会重复打包。

离店前确认当前任务已经结束，再通过访达正常推出SSD。回来后把SSD接回本机，告诉Lead测试了哪台机器、是否有系统阻止提示。无需手工整理日志或把模型上传云端。

## 如何理解报告

执行完成、媒体结构正确和创作质量满意是不同结论。人耳/看图/文字内容检查会保留为待人工判断，不能仅凭一个绿色状态宣称质量最好。MLX分配峰值不是整机内存；RSS采样也不等于去重后的CPU/GPU物理占用。首次完整校验会影响文件缓存，报告不能据此声称磁盘完全冷启动。

本工具验证后端能力；工作台界面、签名跨机器长期有效性、麦克风和音乐理论/精确谱面服从不由这些测试证明。不要在展示机上做完整GUI自动验收或录音。

## 本次制作验收记录

随包的`Acceptance.json`记录本次制作的代码版本、小配置实测及移位检查；其中未执行的项目不算通过。现场结果另存`Results`，不会覆盖制作证据。另一台Mac上的运行和大配置实测必须由现场结果确认。
