# ADR 0006：项目工作台与原生图像界面

日期：2026-09-07。状态：已实施。检查点验收与限制见 [工作台报告](../WORKBENCH_ACCEPTANCE.zh-CN.md)。

## 背景与决定

旧界面的图像历史只保存内存中的 `NSImage`，窗口与视图模型直接依赖旧模型服务。取消立即重置按钮状态，默认参数也不符合已验证的 FLUX.2 管线。这些问题横跨状态、文件与计算所有权；逐个改按钮不能建立可靠的产品流程。

保留 SwiftUI、依赖注入和「资源—作品—参数」的布局方向，重新实现工作台状态与生成路径。首个界面集中于图像项目，文本后端和 CLI 保留，但旧文本／音视频占位入口不进入新应用。旧生成实现留在 Git 历史与暂未迁移的包中，应用目标不再链接它们。

采用现有 `Packages/UI` 作为工作台应用服务、状态和视图的组织单元，不新增独立框架包。它只依赖纯 `DInference`；应用入口装配 `DRuntime` 和 `DMLXBackend`，通过可注入会话提供提交、状态、关闭及清理。模型、任务和项目生命周期由工作台拥有，视图消失不等于任务取消。

## 项目与保存

一个主窗口同时打开一个 `.dproject` 目录包。版本化清单记录项目、未提交草稿、不可变请求、任务、资产与生成条件；作品用相对路径引用，模型权重在项目外共享。保存先登记请求和最终 seed，再提交推理；成功终态要求计算已清理且作品登记已持久化。

元数据以临时文件写入、原子替换。应用保持项目和模型的安全作用域访问权限，外盘不可用时明确报告并要求重新定位，不回退到另一磁盘。关闭／切换遇到运行任务时，提供等待、取消并等待清理、继续编辑；正常退出与关闭共用一次清理和保存流程。

启动恢复将未完成记录标为中断，不自动重跑。已发布 PNG 与清单之间存在通知中断窗口，因此只在本项目已记录任务拥有的目录内检查和登记可恢复图片，保留已发布作品。旧作品不因缺失模型而无法打开。

## UI 和 Liquid Glass

新界面遵循 Apple 的系统设计语言：原生分栏、侧栏、工具栏、检查器和系统控件优先；适用的独立控制使用系统 Liquid Glass API。玻璃服务于导航和控制层，作品区域避免颜色偏染与不必要的透明叠层。遵从系统浅／深色、降低透明度和动态外观；保持可读文字、键盘操作和窗口缩放。不是给每一个容器叠加毛玻璃。

界面固定显示真正支持的 512×512、4 步和 guidance 1；提示词及 seed 可编辑，seed 0 合法，随机 seed 在提交前生成并保存。历史条件复制到新草稿，不修改已有请求。

## 扩展与当前范围

资产身份、文件引用、原始／派生／预览角色、可选媒体元数据和格式版本现在建立；RAW／DNG、高位深 TIFF／OpenEXR 与专业音视频作为后续目标逐项适配。当前不实现通用解码插件，也不把所有媒体假定为 8 位 sRGB。

本检查点仅注册已安装本地模型，检查目录／配置；真实生成前由后端完整校验固定权重。模型下载、安装恢复和版本管理属于下一检查点。目标顺序由 [产品目标清单](../PRODUCT_GOALS.zh-CN.md) 维护。

## 验收门槛

- 项目创建、本地模型注册、真实生成、查看／导出、关闭和重开连成完整流程。
- 多任务不可变请求、seed 0 与随机 seed、可信取消、资源释放后交接。
- 原子保存与失败保护；中断恢复、不自动重跑、已发布未登记 PNG 恢复；移动项目、缺失模型和访问失效可理解。
- 工作台文件操作及校验不阻塞主线程；键盘、窗口缩放与系统外观基本可用。
- 新应用路径不调用旧模型服务；核心回归继续通过；测试和真实推理／UI 证据分开记录。

已执行验证与尚未完成的外观矩阵、XCTest UI 自动化限制分别记录在工作台报告中，不以构建通过代替实际执行。
