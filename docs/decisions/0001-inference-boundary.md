# ADR 0001：D 推理核心边界

日期：2026-09-06。状态：作为本轮最小框架的实现基线；产品范围与长期扩展仍可讨论。

## 决策

D 采用原生 macOS 的模块化单体，推理后端以 MLX 为主。主仓库中的一个内部 Swift package 是新核心的管理单位，target 是代码边界，actor/任务所有者是并发边界。旧六个子模块按能力迁移，避免一次移动全部源码和改写历史。

长期编译模块方向：DInference（契约）、DRuntime（准入与任务生命周期）、DMLXBackend（模型/管线/底层计算）、Workbench（应用服务与UI）。当前仅创建前两个真实模块；不为空助手、音频、视频、工作流、插件分别建立空库。

公共边界采用类型化请求、模型/资产引用、事件和终态，禁止暴露 MLXArray、ChatSession、SwiftUI 或任意类型字典。文本token化和扩散latent属于后端内部。初期text/image请求不是最终专业工作流接口；在真实图像编辑切片中再引入图像/蒙版、LoRA/ControlNet与组件句柄。

外层harness负责项目文档、模型下载/磁盘目录/书签、资产与历史、撤销、预设、工作流组合及助手工具。UI、专业编辑模式、易用模式与助手应共享同一应用命令，不另建一套生成逻辑。数学推理不依赖这些产品对象。

## 取舍

一个包多个target足以定义依赖图。新框架零远程依赖，Swift6严格模式；旧实现继续按原版本构建。额外的根package是迁移目的地，不是第七个独立仓库。最终收敛旧manifest/子模块的时间由后端验收决定。

初版单进程、一个重推理许可。它是稳定性和16GiB设备的策略，不是MLX只能全局串行的结论。没有XPC/RPC、动态插件市场、通用DAG引擎、跨后端tensor交换或磁盘溢出推理。

需要进程崩溃隔离或独立发布后端时再评估XPC/独立package，避免把进程通信当作Sendable编译错误的修复方案。

## 验收

纯核心可在没有MLX、模型、UI与网络的情况下编译测试；错误、取消、资源准入都有确定语义。真实后端迁移后另行验证GPU停止、峰值内存和推理输出，不能用fake backend测试替代。
