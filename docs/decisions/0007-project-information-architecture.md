# ADR 0007：项目、创作文档与共享资源的信息架构

日期：2026-09-07。状态：用户已批准；按阶段实施，不能把此文中的远期结构当作已实现 UI。

## 决定与用户选择

D 的主要组织单位是项目：一项创作可以包含海报、角色设定、分镜、文稿及未来音视频。项目内每份创作文档独立保存编辑状态并共享项目资产。临时尝试未来自动保存为草稿项目，与正式项目使用同一格式和执行服务。用户确认近期先整理服务边界与安装器，多文档导航和快速草稿在安装器之后。

```text
D
├─ 项目
│  ├─ 最近项目／草稿项目
│  └─ 当前项目
│     ├─ 创作文档：海报探索、角色设定、分镜等
│     ├─ 素材与作品：集合、搜索、类型与来源筛选
│     └─ 任务记录
├─ 资源
│  ├─ 模型：可安装、已安装、安装任务
│  └─ 预设与模板
└─ 设置：存储、外观、辅助功能；未来外部连接与自动化
```

这是逻辑归属，不是要求同时展示整棵树。功能未实现前不出现空入口。全局活动只汇总状态并链接到所属项目或资源页面，不成为第二份任务事实来源。

## 内容、操作与呈现分开

| 对象 | 职责／归属 |
| --- | --- |
| 项目 | 一项创作的保存与恢复边界，拥有文档、资产、任务及关系 |
| 创作文档 | 可命名、可继续编辑的一份工作；保存输入引用与编辑状态，可以产生多份候选作品 |
| 资产 | 实际素材或作品的稳定身份；保留原件、派生结果和可重建预览 |
| 任务 | 一次已提交执行的不可变输入、实际参数、状态和结果 |
| 模型 | 应用级共享资源；身份和固定版本不随安装路径改变 |

同一资产可以被多个文档引用，文档结果和项目资产总览指向同一份文件。集合和类型筛选不改变文件所有权。媒体原件不能因为预览格式有限而被覆盖或降位深。

进入文档后按“生成图像”“根据参考图编辑”等实际操作呈现工具和兼容资源。模态可用于新建入口与筛选，不作为隔离项目内容的顶层分区。工作区是工具呈现方式，不是新的项目或复制的内容。

简单与专业模式共用编辑状态、参数验证和提交路径，区别是预设与参数展示。未来节点文档调用相同应用操作。复杂节点图只对外展示明确暴露的参数，不承诺任意图都能无损转换成简单表单。

## 分阶段落地

1. D-M01 提供欢迎界面和项目内均可访问的共享模型管理；继续使用现有单项目、单草稿结构。
2. D-W02 引入独立创作文档、项目导航及带备份的项目格式迁移；旧草稿归入一份默认文档，保留历史归属。
3. D-W03 增加自动保存的草稿项目，默认放用户授权的工作目录；失联时不静默改存另一磁盘，不自动丢弃未整理创作。
4. 集合、搜索、比较、节点、媒体与外部服务按目标清单启动，不因树中有位置就提前实现。

Liquid Glass 用于原生导航和控制。作品画布保持适合准确观察的背景；外观、辅助功能和编辑内容不能依赖玻璃材质才能理解。

## 依据及取舍

- [Photoshop 工作区](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/workspace-overview.html)：文档承载工作，选项和上下文工具随当前操作变化。
- [DaVinci Resolve](https://www.blackmagicdesign.com/products/davinciresolve)：在同一创作环境按任务切换专门工作区。
- [Blender 工作区](https://docs.blender.org/manual/en/latest/interface/window_system/workspaces.html)：工作区组织编辑器和布局，同一项目可切换多个工作区。
- [ComfyUI 子图](https://docs.comfy.org/interface/features/subgraph)：将复杂流程封装并暴露少量控制；不等于任意工作流兼容承诺。
- [NN/g 渐进展示](https://www.nngroup.com/articles/progressive-disclosure/)：常用操作优先，高级控制按需展开。
- [Apple Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)：材质主要服务于内容之上的导航和控制层。
