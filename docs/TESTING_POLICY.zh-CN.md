# 按风险验证与控制工程量

v1 · 2026-10-02。本页是常驻测试政策唯一正文，落实用户《D_Testing_and_Engineering_Policy_v0.1》。权限、隔离、资源、返工预算仍见[协作规程](MULTI_AGENT_WORKFLOW.zh-CN.md)，真实命令见[仓库导航](REPOSITORY_MAP.zh-CN.md)，当前范围见[当前行动](CURRENT_ACTIONS.zh-CN.md)。不追改历史失败、严格契约或已耗预算。

先回答：改了什么、可能坏在哪里、最少哪些互补证据能发现它。优先复用已有测试与有效产物；以下是风险下限，不是每轮全跑或测试数量指标。多个类别取并集去重；升级时用一句话说明原因。代码短、目录名或模型昂贵与否都不决定风险。

| 改动 | 最低必要证据 | 升级触发／避免的重复 |
| --- | --- | --- |
| 文案、注释、纯说明 | 事实/差分/引用，资源格式、键与插值；长度影响时看局部布局 | 稳定ID、默认值、执行模板或解析规则按逻辑验证；不重跑模型 |
| 局部布局、实名和状态展示 | 受影响编译、身份/状态检查、一条原生路径 | 触及焦点/输入/命中/绑定时增加对应交互，不按权重份数重复生成 |
| IME、指针、拖放、窗口 | 原场景最短反例、实际控件原生操作；几何/状态检查，组字/选区/Undo保持 | 共享输入器、sheet、跨工作面或缩放坐标分别覆盖；回调次数和AX填字不代替真人组字，不用GPU验手势 |
| 安装、导入、就绪、下载认证 | 状态与失败反例、小文件/模拟HTTP边界、一条普通App路径 | Range/摘要/原子发布/凭据/原件责任改变时补对应边界；不重复百GB下载、不打印凭据或无变化重试401 |
| 端口、请求、控制、解析 | 权威定义到后端/Quick/Canvas的映射、关键非法组合和旧数据兼容 | 新预处理/条件语义补该真实模式；不做两套笛卡尔积，不拿复制常量作唯一独立期望 |
| 加载、驻留、张量、精度 | 固定来源/布局/数值，真实块或阶段对照，全层完整请求及生命周期 | 架构/精度/缓存/强条件有独有路径则分别覆盖；不以量化/小型/块对照替代原始整模型，不暗换黄金值 |
| 新模型或公开模式 | 输入真正进入计算，合理正常采样代表请求、可核对输出、正常产品接入 | 强条件走不同计算时另补一例；不穷举seed/时长/尺寸，一步/非空不等于可用成品 |
| 运行时、取消、进程、所有权 | 队列/终态/错误优先级/释放反例，实际不同生命周期代表运行 | 共享锁或协议改变时覆盖不同实现族；仅cache为零不证明完整清理 |
| Store、迁移、保存、导出 | 真实小文件/清单正常、失败、中断、恢复；原件/版本/不覆盖 | 新媒体/跨项目/schema/原子语义补相关场景；复用不可变产物，不为每条保存断言重生成 |
| 打包、依赖、签名 | 固定候选构建、依赖核对、正常签名App启动、受影响引擎/准备入口 | 数值库/环境变化扩大受影响模型族，发行另做清洁环境；编译不等于沙盒通过，不无因重装 |
| 组合与冻结 | 明确组合版本的相关集成、高风险与代表原生路径、缺口和交付包核对 | 多切片相互影响/共享契约/证据不足则扩大；文档提交不刷新GPU验收时间 |

## 证据如何复用

记录须能定位源码/依赖、固定模型revision与dtype、加载策略、关键输入/随机参数、环境、实际命令与结果。只改文档/展示且已核相关执行差分，旧模型结果标“沿用”；改预处理、权重/采样/精度/缓存等则复验受影响路径。Store改动用旧不可变产物测试新Store，不能沿用旧Store通过结论。一次生成可共用解码、预览、来源、保存重开和导出，但关键断言/故障独立可定位，不能首次失败默默跳过其他项。

Quick/Canvas共用请求时，用共享映射检查加各自代表入口；独有路径单独补，不把GPU次数机械翻倍。相关源码/依赖差分无法确认就标证据待核。测试发现为空集合、无有效筛选或仅语法成功，不算行为测试通过。

## 数值、生命周期与成本边界

- 下载、完整权重校验、冒烟、正常代表生成、条件效果、普通App、真人听感分别报告。原始/量化、常驻/SSD分开；块级常驻对照不称大模型整体常驻通过。缺大内存只保留独有未验项，不取消原精度目标。
- 文件转换/身份用严格摘要；数值差异按事先约定的精度标准，先归因，不因失败降阈值；也不无依据强求跨实现逐比特相同。控制须核实际输入及代表效果；视频时序须真正多帧，不只断言非空或固定自由回答措辞。
- 用户接受慢；保持合理采样、全模型和完整条件。使用任务明确watchdog和程序低频监测；工具等待超时不意味着作业结束或可重复提交。
- 不为测试方便在每次执行重复全权重hash、转换、全库扫描、重建文本控件；跨进程、外部可写、内容变更等真实风险保留明确边界检查。先定位重复成本与所有者，不一刀切取消不同层保护。
- 合法有界缓存与持续残留分开；既有严格释放契约不临时放宽，不清别的任务状态。调试默认关闭，仅合成/脱敏资料；不用全局hook、定时器或强制焦点做产品补丁。
- 同代码/输入/环境/假设且已足够诊断的失败不机械重复；修后跑相应反例。疑非确定性时预设少量有目的重复，不跑到碰巧绿。401/403、锁屏/设备等只在状态变化后重验。
- 测试驱动不适用可说明原失败、丢失/补充覆盖并替换正确层级；不得只删失败断言。新增抽象须有真实复用，不建测试调度平台、快照库、成本数据库，不按条数或行数生产测试。

## 最小记录与出口

普通改动在既有任务记录一行：`改动/风险 → 最小检查 → 沿用证据及理由 → 升级条件`。高风险实现由非实现者针对性审阅，不要求审阅者重复GPU。结果记录`代码/产物、命令和有效筛选、执行/通过/失败/跳过/未执行、关键配置、产物索引、复用与剩余项`；大日志/媒体留外盘，未知费用就unknown，不套API标价。

冻结须闭合约定能力、数据安全和基本交互，版本与证据相称。轻微问题只有影响明确且已获接受才可保留；输入丢失、错误模型绑定、损坏作品、未实现原生承诺、关键不可操作不能改写为未来。试用就绪、功能冻结、发行就绪独立；不要求穷尽全部设备/输入，不扩大当前范围。
