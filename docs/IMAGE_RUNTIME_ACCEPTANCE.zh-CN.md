# 正式图像核心 B2 验收（2026-09-07）

本阶段对应已批准路线的第一阶段：把图像实验接入正式运行时。完成边界是文本与图像共享任务调度、计算所有权和生命周期，可靠地产生可交付图片；不是“可靠出图 Alpha”或旧 UI 接入完成。

## 实现

- 现有 `DInference` 的 `ImageRequest`、进度事件、文件引用和 `InferenceResult` 直接复用，`DRuntime` 不增加 MLX 依赖。
- `MLXImageBackend` 加入现有 `DMLXBackend`，与文本后端共用进程级执行许可。加载、编码、去噪、解码分阶段，取消和抛错先 drain，再 release，清理完成后才交接下一任务。
- 固定 FLUX.2 Klein 4B q8、512×512、4 步、guidance 1。提示词和 seed 开放；未支持的参数拒绝。512 token 条件完整保留，模板后超长输入在大权重加载前明确失败。
- 完整固定模型清单、元数据准入、流式 SHA-256 和文件替换检查；推理本身无模型下载。
- 私有任务目录、实际写盘后 PNG 解码和内容验证、不覆盖发布、保留已交付图片、由宿主显式清理未发布文件。
- Flux2 同仓固定源码、许可证、三项最小补丁、完整来源校验；随机状态每任务持有，没有全局 seed 修改。
- 命令行增加图像模式和产物 JSON Lines；保留文本默认行为、信号处理、取消、报告与断管清理。

## 本机实测

硬件为 Apple M4／16 GiB，模型、构建缓存、测试临时文件和运行证据使用外置 SSD。首正式运行包含完整模型内容校验，耗时 **39.751 秒**；MLX 分配峰值 **6,207,522,060 字节（5.781 GiB）**。

固定红色茶壶提示词、seed 42 的 PNG 为 **427,767 字节**，SHA-256：

```text
05f0b80ac7d9d6e4ffa105af12a8805cdea4425a9448f9d35a1bd9d8f8dda553
```

它与 B1 已审阅图片逐字节一致。数值验证直接调用生产 scheduler、去噪 step 和 VAE decode helpers；五项参考比较包含 prompt embeddings、text IDs、latent IDs、packed latents、decoded pixels，ID 完全一致、浮点满足固定容差并拒绝 NaN/Inf。PNG 测试另外用已知 2×2 RGB 检查实际颜色与像素布局。

### 0.5 MiB 残留的对照解释

| 实验 | MLX 活跃分配 | MLX 缓存 | 说明 |
| --- | ---: | ---: | --- |
| B1 原始三轮末尾 | 524,304 B | 0 | 旧图像缓存与全局随机状态仍持有资源 |
| B2 正式计算 drain 后 | 524,288 B | 268,435,456 B | 模型／任务随机状态已释放，Flux2 attention mask 仍在缓存字典 |
| B2 显式 Flux2 clear + allocator clear 后 | 0 | 0 | 512×512×2 字节的 mask 被实际释放 |
| 单独进程：局部 RNG 生成相同形状噪声后退出作用域 | 0 | 0 | 不建立全局常驻随机状态 |
| 单独进程：全局 RNG 生成相同形状噪声后 | 16 B | 0 | 全局 state 仍持有 split key 的分配 |
| 单独进程：全局 state 重新 seed | 8 B | 0 | 旧 split 分配被新的常驻 key 替代；全局 owner 仍存在 |

独立 RNG 对照和正式 cache clear 共同支持 B1 的 `524288 + 16` 归因。修复没有把 524,304 字节加入“允许残留”阈值。小 fixture 还单独记录 allocator clear 不改变活跃分配、Flux2 clear 释放其引用、任务随机状态离开作用域后归零；其缓存可能持有未求值的小计算图，不能套用真实 512 序列的 mask 大小解释所有 fixture 数字。

随机对照可通过构建 `mlx-allocation-probe`，在独立进程执行 `--rng-ownership-control` 重现。不要把故意使用全局 RNG 的对照与要求 0 活跃分配的集成测试放在同一进程。

这些是 MLX allocator 指标，不等于操作系统进程 RSS；有限重复验证也不能证明任意模型、负载和运行时长完全无泄漏。

## 验收覆盖

纯框架回归通过 **17 项声明／18 个展开场景**。MLX 集成实际执行通过 **61 项声明／120 个展开场景**，失败、跳过和预期失败均为 **0**；测试执行耗时约 **571.6 秒**。旧应用 Debug arm64 构建通过，最终文本 CLI **10/10**、图像 CLI **17/17** 通过。最终图像 CLI 三轮分别 **38.896／39.634／39.979 秒**，每轮 MLX 分配峰值同为 **6,207,522,060 B**，释放为 **0／0**；同 seed 的三张 PNG 摘要一致。程序化 step 取消约 **0.063 秒**到终态，SIGINT／SIGTERM 则分别等待约 **7.127／7.134 秒**，验证了进行中的计算段先 drain 再结束。

最终执行计数、最终 CLI 数据与原始日志摘要见同仓 [B2 机器证据](research/IMAGE_RUNTIME_B2_EVIDENCE.json)。

| 检查 | 覆盖 |
| --- | --- |
| 纯框架 | 原有队列、预算、取消、终态、重入回归 |
| 模型文件与 PNG 文件系统 | 固定参数／来源、缺失和损坏文件、符号链接和替换文件、写失败、不覆盖、清理归属、精确像素 |
| 小型数值与缓存 | 5 个参考输出和缓存／RNG 所有权对照 |
| 真实图像运行时 | 三轮相同 seed、12 个阶段取消点（含 drain 后取消）、图→文→图队列交接、两类消费者抛错与恢复、损坏 VAE 副本、输出目录失效、超长提示 |
| 真实文本回归 | 文本流、token 上限、取消、部分加载失败、消费者失败、重复释放 |
| 真实 CLI | 图像三轮、取消、SIGINT、SIGTERM、断管后保留产物、预算拒绝；文本原有 10 类进程检查 |
| 旧应用 | Xcode Debug arm64 构建，不把构建通过等同于接入新图像运行时 |

阶段取消通过门闩暂停在真实生命周期位置，再取消并放行，验证后续计算阶段不执行且 release 为 0/0。信号取消则在真实 step 完成通知后异步发出，可能需要等待正在运行的下一 step；不承诺瞬时停止。

损坏模型测试只修改测试自己的 COW 文件副本，验证原始文件没有改变。目录失效通过移动测试自己的空作品根目录模拟；权限写失败通过自有目录权限触发。没有填满 SSD 或物理拔盘；真实磁盘耗尽、硬件故障和跨进程持续竞争写入仍需要 Alpha 阶段故障验证。文件保存错误会明确返回失败，已存在或已发布的图片不会回滚删除。

## 仍未完成的产品能力

旧 SwiftUI 界面尚未迁移；模型安装状态、跨重启外盘 bookmark、作品库、项目恢复和日常任务面板属于下一阶段。B2 的 PNG 与 CLI 报告没有冒充完整作品项目。后台安装必须维持模型版本不可变；完整校验结束后，其他同权限进程的修改仍超出当前安装隔离保证。

图片发布与事件送达不是跨组件事务：若文件已发布、但取消或事件流拒绝发生在产物通知送达前，图片会保留，报告可能没有直接产物引用；仍可通过作品根目录中的请求 UUID 找到任务目录。后续作品库应在保存与恢复时登记这些产物。CLI 断管测试的引用保留保证针对“已经收到产物、随后 stdout 写入失败”的路径。

本阶段只支持固定模型与参数。参考图编辑、更多模型、LoRA、批量创作、节点编辑、AI 助手、音视频和并行优化保持后续路线，不在本次交付中新增占位包。
