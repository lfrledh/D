# B1 图像推理可行性与实测结果

2026-09-06，固定版本 FLUX.2 Klein 4B q8 在本机 Apple M4／16 GiB 上通过隔离的真实文生图验证。512×512、4 步、完整 512 token 文本条件，同进程三轮各约 35 秒，MLX 分配峰值均为 6,207,522,060 字节（5.781 GiB）。这是开始实现正式图像后端的可行性证据，尚未完成 DRuntime 接入、应用 UI 迁移或整项图像阶段。

## 验证范围与结果

| 项目 | 实际结果 |
|---|---|
| 硬件／构建 | M4，16 GiB；macOS 26.6.2，Xcode 26.6；Debug arm64 构建通过 |
| 固定模型 | `mzbac/FLUX.2-klein-4B-q8@ef52ee019fd1d0e75ae4deb40476ba65989716d7` |
| 模型完整性 | 18 项，9,426,536,934 字节，完整文件 SHA-256 全部通过；权重在外置 SSD |

| 真实生成 | 同进程三轮，分别 34.957／34.521／35.415 秒；每轮完整加载、编码、4 步去噪、解码、PNG 回读与释放 |

真实图像提示词为窗边木桌上的红色陶瓷茶壶。人工打开首张 PNG，茶壶、木桌、窗边光线与提示词相符，画面与颜色正常。这是一张固定场景的视觉检查，不能代表中文、多主体、文字绘制或图像编辑质量。

## 分阶段内存行为

首轮编码器本体约 4.866 GB；编码条件求值后退出函数作用域，活跃分配降至 16,267,264 字节，再加载 Transformer。去噪完成并释放 Transformer 与条件后，降至 1,064,976 字节，随后单独加载 VAE。这样没有要求三个模型组件同时常驻。

| 计算阶段 | 首轮 MLX 区间峰值 |
|---|---:|
| 文本编码 | 5,737,351,292 字节 |
| 去噪 | 6,207,522,060 字节 |
| VAE 解码 | 4,445,903,042 字节 |

进程自身报告的 RSS 生命周期高水位最高为 3,856,154,624 字节（3.591 GiB），父进程每秒采样的最高 RSS 为 3,496,214,528 字节。采样会错过瞬时峰值；RSS 与 MLX 统计覆盖范围不同，不能相加，也不能把 MLX 峰值称作整台机器的内存用量。900 秒／13 GiB 采样阈值的进程保护没有触发。运行前系统 swap 使用为 0，运行中观测到约 81.25 MiB；这是全系统读数，不能全部归因于本探针，也不能宣称“完全没有交换”。

524,304 字节残留与源码中未暴露清理入口的静态 attention mask cache 及全局随机状态相符，但本次没有做逐项清理对照，不能把全部归属视为已证明。三轮固定形状稳定是有限的趋势证据。正式后端接入前，应提供受执行许可保护的缓存清理／作用域策略，并验证失败、取消与不同形状下的释放，不能用这里的固定残留基线笼统放行所有增长。

## 依赖选择与实现方式

候选 [flux2.swift 固定源码](https://github.com/mzbac/flux2.swift/tree/959a4af7c0721c800851c84431ffd3fa1f353f1f) 与 D 的 MLX 0.30.6 修复版及 transformers 1.1.8 兼容，能直接加载预量化权重。其高层构造器会同时持有 Transformer、VAE 和文本编码器；生成循环也没有 D 所需的取消、逐步 drain 和释放契约。本实验复用公开底层 API，按阶段管理所有权，每步显式求值；没有重写模型数学，也没有修改临时 SwiftPM checkout。

当前 `Experiments/Flux2Probe` 是有实际使用者的独立可执行实验，不加入根核心 package 或旧应用依赖图。它复用了已经固定的本地 MLX vendor，并把 flux2.swift 的提交及其余依赖锁定。基础模型和量化来源、许可证文件是否存在的事实、两个摘录 schedule helper 的来源，见 [实验说明](../Experiments/Flux2Probe/README.zh-CN.md)。

旧图像路径的错误维度、重复颜色变换、丢失本地目录、取消任务无所有权和吞错问题记录在 [旧后端审阅](research/IMAGE_BACKEND_REVIEW.zh-CN.md)。这些旧问题没有因本实验成功而自动修复；旧 SD3 入口仍是 stub。

## 下一工作包与验收边界

下一步在现有 MLX 集成边界内实现一个真实 `.image` 后端，复用 DInference 的请求、进度和产物引用，不让 MLXArray 跨入公共契约。沿用 DRuntime 的执行许可和 drain/release 顺序，整合分阶段加载与明确错误；先限制为已验证的固定模型和尺寸，再根据新实测扩大能力。

正式适配的验收应覆盖正常产物、消费者失败、不同阶段取消、部分加载失败、取消后队列交接、缓存清理及重复加载/卸载。当前 `--stop-after-step` 只是同步边界主动退出，没有验证生产异步取消或信号处理。更大分辨率、图像编辑、多参考图、图像批量、LoRA、中文质量、其他量化规格、Release 性能与长时间运行都未在 B1 验收。

复现入口：`./Experiments/Flux2Probe/build.sh`、`python3 Experiments/Flux2Probe/validate.py`；首次需要按 [说明](../Experiments/Flux2Probe/README.zh-CN.md) 下载模型。原始完整证据目录为 `/Volumes/CodexProjects/Codex/D-Development/Logs/flux2-probe-b1`，下载过程和初始来源校验位于同级 `Research/Flux2Probe`；随仓精简记录见 [B1 证据](research/IMAGE_PROBE_B1_EVIDENCE.json)。

本轮没有修改旧应用或文本后端实现，因此没有重复执行与改动无关的完整文本 XCTest／应用测试；这些能力的最新验收仍以基础阶段记录为准。
