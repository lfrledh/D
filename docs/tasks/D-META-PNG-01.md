## Frozen codec interface (implementation choices otherwise free)
Use existing GenerationRecipe, RecipeDisclosure, GenerationRecipeCodec. New public PNGRecipeInspection: Sendable with let recipe: GenerationRecipe?, mediaPayloadSHA256: String, width:Int, height:Int. New public PNGRecipeCodec enum with static inspect(_ png:Data) throws -> PNGRecipeInspection; static embedding(_ recipe:GenerationRecipe, in png:Data, disclosure:RecipeDisclosure = .publicShare) throws -> Data. Public equatable Error enum PNGRecipeError: invalidPNG, unsupportedPNG, sizeLimitExceeded, duplicateRecipe, unsupportedRecipe, invalidRecipe, privacyConflict.

PNG signature; bounded complete chunks, big endian lengths, CRC for every chunk, valid ASCII 4-letter type and reserved bit, one first 13-byte IHDR, legal standard bitDepth/colorType pairs, dimensions1...8192 and <=16,777,216 pixels, compression/filter0/interlace0or1; required consecutive IDAT with nonempty combined payload; exactly one final zero-length IEND; no trailing bytes. PLTE ordering/size and requirement for indexed color; reject unknown critical chunks and APNG (acTL/fcTL/fdAT) as unsupportedPNG. Do not decompress IDAT, ICC or text. This is a bounded structural gate, not proof that pixels decode; Lead will use ImageIO for actual display/publication validation. PNG <=32MiB input AND output; <=4096 chunks; recipe JSON <=128KiB inherited codec, no dependency.

One uncompressed iTXt with exact case-sensitive Latin1 keyword org.d.generation-recipe; compression flag0/method0, empty language/translated keyword; UTF8 JSON envelope unchanged from existing component. Same keyword in tEXt or zTXt -> unsupportedRecipe, not silently ignored. Duplicate keyword across supported textual chunks -> duplicateRecipe. D iTXt compressed/malformed header -> unsupportedRecipe or invalidRecipe (bounded deterministic); bad/unknown envelope -> invalidRecipe; no recipe -> inspection.recipe=nil (not unknown empty success). External claim stays callerDeclared per existing decoder. No URI access, instructions execution, downloads, filesystem calls or networking.

Preserve every non-D chunk in original order and exact bytes. Replace one valid existing D chunk; otherwise append D iTXt immediately before IEND. Malformed/duplicate existing D data is rejected, not fixed. Compute mediaPayloadSHA256 as SHA256(PNG signature + full original non-D chunks including lengths/CRC, in order); it is a precisely documented exclusion digest, NOT final-file digest. Embedded recipe takes computed digest; known width/height must equal IHDR, mismatch invalidRecipe; unknown remains unknown. On inspect a known digest/dimensions must match, invalidRecipe otherwise; absent digest remains unknown, never claimed verified. Countercheck semantic readback before returning embedding. No file writes.

Public export uses GenerationRecipeCodec public projection (prompt/structuredInput withheld, parents removed). Because copying unknown source metadata can leak secrets, public export must REJECT privacyConflict when non-D chunks contain anything beyond IHDR/PLTE/IDAT/IEND/tRNS/cHRM/gAMA/iCCP/sBIT/sRGB/cICP/mDCV/cLLI/pHYs/bKGD. In particular all other text, eXIf and unknown ancillary chunks refuse public mode; private mode preserves them exactly. This deliberate limited compatibility must be stated, not advertised as universal sanitization; visual content itself is not redacted. Color/profile bytes retained unchanged; private eXIf orientation bytes preserved. Current app-generated PNG is within supported scope. Neither mode changes pixels or silently overwrites an original.
