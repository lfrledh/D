# D：四模态快速生成 UI 设计决议

**版本：** v0.2 · 2026-10-07（Asia/Tokyo）  
**性质：** 对当前对话中 UI 讨论成果的存档；供下一阶段设计、原型与实现时使用。  
**状态：** 保留 v0.1 的有效空间决议，并纳入后续已获认可的交互边界与模型能力契约原则。具体控件、断点及 API 映射仍待原型与实现核实。不是已实现报告，也不是立即启动生产 UI 改造的授权。

**阅读方式：** 第0–14节保留初版内容，避免遗漏已确认决定；第15–25节是本次补充。重复主题按补充后的更精确规则理解。新增章节中的“例子”不声明某个现有模型已支持相应能力；“待定”不自动成为首发新增功能。F26 真实搜索调用和凭据验收已获准延期，不阻塞当前转段。原版保留，此文件作为后续讨论的合并基线。

## 0. 阶段与边界

当前仍优先关闭影响基本操作的 Bug 和既定功能验收缺口。模型推理加速等深入性能优化可以持续到 1.0 发布后；输入、停止、滚动、导航、保存与恢复的基本可靠性不能延期。

本文件描述的全局布局与视觉统一，在关键 Bug 收口、功能与数据关系稳定之后、正式发布之前实施。当前不为它重做生产前端，不用 UI 改版掩盖尚未解决的 Bottom 卡顿，也不要求“全仓库绝对零 Bug”才允许设计。

沿用原 F01–F36 和此前确定的模型／资产／工作流能力。本文件是这些能力的展示与交互设计，不增加新的生成能力、模型家族、工具平台或多轨编辑器。LoRA、ControlNet 等控制生态仅在实际已适配时展示；预留组织方式不等于本轮追加实现。

## 1. 产品空间：四模态共用一套骨架

快速生成采用“中央结果工作面＋四周浮动组件”。文字、图像、视频、音频使用相同的区域分工，但中央内容组件和必要参数随模态变化。

这里的“画布”指快速生成的视觉工作面，不是节点工作流，也不是自由摆放气泡的图形编辑器。聊天仍保持有顺序、可滚动的消息流；不会要求用户像排节点一样整理对话。

| 区域 | 已确定职责 | 不承担的职责 |
|---|---|---|
| 顶部左侧 | macOS 原生红绿灯和必要窗口拖动留白 | 不自绘系统窗口按钮；不挤入模型参数 |
| 顶部中央 | 条形四模态切换：文字／图像／视频／音频 | 不是任务大全，也不按模态拆成四套数据系统 |
| 顶部右侧 | 当前工作模式及直接切换入口 | 不随侧栏收起、正文滚动或空闲空间变化而移动 |
| 左侧浮动面板 | 模型选择、就绪状态、参数、已适配控制生成设置 | 不混入全部资产历史，也不常驻全部诊断 |
| 右侧浮动面板 | 资产库、候选与成果、参考材料及相关整理功能 | 不重复复制一套模型安装管理 |
| 底部浮动输入组件 | 提示词／聊天输入、附件、语音等输入辅助、发送／停止 | 不铺满所有高级参数；不遮盖末行文字 |
| 中央内容区 | 当前模态的生成结果与直接相关操作 | 不沦为被四边栏挤剩的小预览 |

左、右面板不顶到窗口最上沿，起点位于顶部控制区下方，为系统窗口按钮、模态栏、工作模式入口留出空间。顶部背景可以与画布连续，不要求存在一条实心横栏。

## 2. 工作模式与模态是两个层级

右上角显示当前模式，例如“快速生成 ⇄”或“节点工作流 ⇄”。点击文字及其完整命中区域，直接切换到另一模式，不先打开菜单再选一次。悬停提示说明将去往哪个工作模式。

这个方案替代先前“左上角模式入口”或“找一个空闲角落动态放置”的建议。红绿灯固定在左，工作模式入口固定在右。两种模式的控件占位尽量稳定，避免标题长度变化推动其他控件。

四模态栏只负责快速生成的主要用途导航。进入节点工作流后，不据此将节点画布再分成四个互不相通的模态。节点模式中顶部中央的具体内容尚待单独设计。

模式与模态切换都是视图切换：不自动取消、提交、下载、加载模型，也不丢失任务、草稿、附件或结果。实际执行仍遵守已有队列与资源调度。

## 3. 左侧：生成配置与控制

左侧内部按“模型 → 常用参数 → 附加控制 → 高级详情”组织。

- **模型身份：** 显示真实模型名称和准备状态；能力可以作为标签，不用“AI 生成”一类通用动作替代模型名字。
- **常用参数：** 随所选模型的实际契约提供，常用项直接可达；低频项可以折叠，但不能永久隐藏已适配能力。
- **附加控制：** 参考图、音轨、结构约束等用有类型的槽位和明确标签；只展示模型与软件实际支持的方式。
- **高级详情：** 版本、具体实现、实际请求和来源等按需查看，不常驻挤占工作面。

分类不限制输入：文字视觉模型仍可接收图片／视频；视频有音轨时完整保留；多能力模型共享一份安装和能力定义。

高频动作如模型切换不得进入多层子菜单。左侧设置不是所有工具开关的唯一入口；本轮发送相关的快捷状态可在输入组件中显现，详细配置仍有稳定归属，避免重复控制同一值。

## 4. 右侧：素材、结果与整理

右侧承载当前工作相关资产及整理功能，沿用共享资产、项目、版本、标签和来源系统。

可从本次候选、项目素材、已保存成果和共享库等视角筛选；它们不必是四份复制数据。右侧具体页签、标签和层级尚未定稿，不能把讨论中的示例分类都做成永久一级入口。

选择、预览和采用分开：浏览素材不自动运行；加入输入后显示实际绑定的参考／附件；移除待发引用不删除源素材。跨项目或复制入库遵守已有文件和资产规则。

最终结果集中显示在中央；右侧提供候选切换、浏览与管理，不把中央再缩成侧栏里的小缩略图。

## 5. 底部：完整输入组件

视觉上是一块完整的液态玻璃组件，内部从上到下分为：

1. **附件与已采用材料区：** 无材料时不占不必要空间；有材料时显示卡片、范围与采用状态，能直接预览／移除。
2. **文字编辑区：** 宽敞、稳定，不能在最后一行叠加按钮。
3. **操作行：** 左侧为附件、语音等少量图标入口，右侧为稳定主操作。

小图标不等于小命中范围。高频且含义不明显的动作可辅以短文字；图标有工具提示与可访问性名称。

**主操作保持同一位置：** 空闲时发送／生成；运行中停止；已请求取消时“正在停止…”；真实资源释放后恢复可执行状态。必要时明确正在控制哪个会话或任务，不停止错误对象。

语音入口可在输入组件内展开录音／转写状态，结果经审核采用到草稿，不覆盖用户已有文字，不自动发送。附件点击直接进入来源选择或文件选择，不穿过多层“工具”菜单。

长文字使组件适度增高，达到合理高度后编辑区内部滚动。具体高度上限在原型阶段决定，不设为无限扩张。

复用已修好的组字安全输入组件。保存 revision、流式输出、布局变形和视觉设置变化不得重新创建编辑器、抢焦点或丢失未提交组字。

## 6. 中央：按模态使用适合的结果组件

| 模态 | 中央基本形态 | 约束 |
|---|---|---|
| 文字 | 有序聊天气泡／消息卡片，包含正文和相关状态 | 支持历史、分支、思考和真实工具活动；不做自由漂浮无序消息 |
| 图像 | 大幅图像展示、候选切换与查看 | 参数退到侧边，结果居中；保留实际元数据 |
| 视频 | 大幅播放器、进度与候选 | 伴随音轨完整播放；不扩成专业剪辑系统 |
| 音频 | 先采用播放器、进度条、时长与候选；必要时显示已支持的歌词／结构信息 | 先保证试听和保存，不为视觉统一扩成 Logic Pro 或多轨编辑器 |

正文、思考、工具活动、错误和不完整状态须区分。界面只展示实际返回／执行的信息，不生成伪思考、伪联网或伪进度。

## 7. 消息操作：悬停显现，不追逐按钮

### 普通阅读

正文和必要身份／状态为主。错误、截断、取消和运行状态不能因为鼠标不悬停而消失。

### 悬停或键盘聚焦

显示少量高频按钮和相关信息。工具条位于消息边缘或预留留白，与正文有连续命中区域；悬停本身不改变气泡尺寸、不移动其他消息。

不能出现“鼠标经过 → 消息变高 → 按钮移开 → 悬停消失 → 消息又缩回”的循环。相同操作也可通过键盘和可访问性入口到达，不把悬停作为唯一方式。

### 点击后展开

复制等瞬时动作不触发重排。短暂且不遮住必读内容的小菜单可以浮起；需要持续阅读、编辑、比较或设置的操作，使用消息附属面板或适合的工作区，实际占据布局空间。

其他消息为展开内容让位，但当前消息和触发位置尽量稳定：下方有空间时后续消息向下顺延；靠近底部时可适度上移内容以容纳面板。不把“所有气泡固定上移”当作唯一规则。

展开后保持稳定，直到用户完成、取消或显式关闭；不因鼠标移开就自动消失。不用多级子菜单代替高频编辑和候选操作。

## 8. 悬浮与避让：内容优先于透明效果

核心原则：**视觉上悬浮，布局上有位置；透明度不用于补救内容遮挡。**

- 四周组件可以悬浮于空白画布，保留边距、轮廓和层次。
- 中央内容应知道可用区域；输入变高后末条消息仍可完整滚到其上方。
- 侧栏展开时通过布局与可视区域协调，尽量不盖住关键图像／正文。
- 持续展开的消息面板参与内容流；避免用每帧碰撞检测和反复 scrollTo 指挥气泡躲避。
- 短菜单与提示的少量重叠可接受，前提是不会同时遮住必须阅读的正文或触发控件。
- 装饰边缘、阴影可以交叠；重要文字、按钮和正在操作的内容不能相互覆盖。

## 9. 边栏与模态切换动效

边栏可展开、收起，默认尽量轻量，始终优先保留中央工作面积。收起后有固定、可发现的入口，不依赖隐蔽的窗口边缘热区。

用户显式展开的面板不会因为鼠标离开而自动关闭；拖入素材、编辑参数或输入时，操作目标不能自行移动。

模态切换保留统一空间骨架。上个模态组件可移出、下个模态组件移入，过渡表达状态变化，不等于销毁／重建业务状态。具体共享哪些外壳和哪些内容参与移动，在原型阶段确定。

动画可被新操作打断，以最后选定模态为准，不排队播放多次过场。需要移动输入宿主时，应先保持或正确提交其编辑状态，不能牺牲输入法可靠性。

## 10. Liquid Glass 与用户外观选择

**最新明确决议：聊天气泡可以使用 Liquid Glass。**不能因为先前曾建议“正文用更安静材质”，就在后续总结或实现中把气泡玻璃选项删除。

四周面板、消息气泡和操作组件属于统一设计语言，但不要求每一层、每个图标都包一块玻璃。玻璃强弱可以因控件用途而有层次；用户实际阅读体验是约束。

“设置 → 外观”集中提供以下方向：

| 设置 | 行为要求 |
|---|---|
| 跟随系统／自定义 | 默认方向为尊重系统偏好；明确显示当前采用方式 |
| 背景透明度 | 调整底板的通透／着色表现，不能通过整组件 opacity 让文字和图标同时褪色 |
| 动效强度 | 与透明度独立；从关闭到克制／完整的层级及具体刻度待原型确定 |
| 轻量外观 | 在实现上减少昂贵效果，不只是提高底色不透明度，底层还照常计算全部特效 |
| 小型实时预览 | 包含气泡、输入组件和按钮；改变显示，不修改聊天内容或推理参数 |

候选提示文案：

> 较强的玻璃与动态效果可能增加图形渲染开销。出现滚动不流畅或耗电增加时，可降低动效，或使用轻量外观。

提示不是卡顿免责说明。合理默认外观应满足基本响应要求；关闭动画后仍需有选中、悬停、按下、任务状态等反馈。默认不让每个静止气泡持续循环装饰动画。

尊重系统“减弱动态效果”“降低透明度”“提高对比度”等设置。具体系统级可用项、材质变体和自定义参数映射，进入实现时以目标 macOS／SDK 的公开 API 核实，不在本文件中承诺任意折射／模糊强度都可连续控制。

不锁死于开发机作为唯一目标，也不把高配用户的显示选择永久关闭；但强效果不能改变模型能力与数据安全。

## 11. 高频操作与全局状态

发送／停止、模型切换、添加附件、主要结果／候选操作、关闭／返回等保持显著而稳定的入口。低频参数与技术诊断可折叠或进入一级更多菜单；不把高频动作层层嵌套。

一块组件中避免大量按钮等权常驻。按“主操作—就近高频操作—低频更多—技术详情”安排，不能为了少按钮而隐藏所有能力。

每个模态保留最近模型、草稿、附件、结果与必要阅读／预览状态。聊天保留会话和分支；节点画布保留位置和选择。模式切换只改变显示，进行中的任务仍由原运行上下文承担。

要保存的是业务与编辑状态，不是为了保留状态让四套隐藏原生输入控件同时活跃。具体视图生命周期方案应由实现阶段结合当前代码选取。

## 12. 未定稿事项：下一阶段再决定，不自动扩为任务

1. 会话列表的最终位置和展开方式。曾建议文字内容上缘放会话名、新建、历史入口，必要时展开列表；尚未决定是否并入左栏或使用独立可固定区域，不新增第五块永久常驻边栏。
2. 右侧资源视角的确切名称、页签数量及项目／共享库筛选方式。
3. 默认哪些面板展开、宽度范围、窄窗口折叠策略和响应式断点。
4. 消息工具条的首批高频动作、附属面板的展开方向和候选比较的具体形式。
5. 玻璃与动效各档的默认值、过渡时长、曲线、透明度刻度及系统 API 映射。
6. 节点工作流模式的顶部中央工具区；本文件不重做节点内部布局。

这些选择应在真实内容原型中确认，不先以一长串猜测参数固化实现。

## 13. 以后交给实现 agent 时的验收重点

此处只保存设计验收意图，不要求现在新建测试工程：

- 普通用户能直接找到模式／模态切换、模型、附件、发送／停止及关闭入口。
- 悬停不引起气泡跳动；展开面板不遮挡必读内容；取消可返回原阅读位置。
- 最后一条消息和输入区互不遮挡；长文本、代码、表格和媒体不破坏可用区域。
- 侧栏收起有稳定入口；窄窗口仍能操作；系统窗口控制与拖动区保留。
- 连续快速切模式／模态不丢草稿、附件、分支、结果和在途任务归属。
- 视觉调整不重建输入宿主、不丢组字；高低动效均保留准确任务反馈。
- 透明度改变不降低正文可读性；轻量外观有真实减负效果。
- 原有模型、控制、资产、版本、请求与导出能力不因界面重排缩水。
- 修改后回归受影响交互和数据路径；不因视觉改版无差别重跑全部模型。

## 14. 一句话设计目标

**让用户看到玻璃组件悬浮在同一创作画布上，操作时却获得固定位置、清楚分工、内容避让和稳定反馈；功能多，不等于按钮四处堆积。**

## 15. 本次新增共识与范围解释

最新共识不是换一套空间布局，而是使现有布局具有可执行的行为规则：

- 借鉴成熟实现对边界的处理，不要求照抄布局、采用其技术栈或购买组件。
- 下一次请求、当前查看的结果、右侧选中的素材、实际运行中的任务是不同对象。
- 空间不足、滚动与重排、输入法、焦点、拖放、异步完成和错误恢复必须有明确规则。
- UI 随具体模型、变体、操作及适配器变化；同一模态不代表拥有同一套参数。
- 模型能力、后端承诺、展示方式、运行准备状态分层；Quick 与节点读取同一份版本化能力契约。
- 模型支持但 D 尚未适配，是适配缺口，不是模型不支持；后端已承诺的用户能力，不应因界面简化而没有可用入口。
- 软件预处理、后处理和多次调度可以复用，但要与模型原生能力区分；不为了一个不支持的模型虚做无效参数。

这些原则服务于已冻结功能的完整展示和未来扩展。它们不自动把所有上游模型的新能力、ControlNet/LoRA、文件承诺、多轨编辑或新的模型操作追加到当前收口。当前直接影响正确性的缺陷继续修；全局视觉、架构减负和推理优化仍按既定阶段进行。

## 16. 空间不足与明确的操作对象

### 16.1 响应式规则

宽敞时允许左右面板并列；紧凑时优先保留中央可用内容、输入、发送/停止与关闭入口。面板可暂时折叠或按需切换，而不是无限压缩正文、图标或字体。具体宽度与断点仍用真实内容原型决定，不在本版写死。

用户主动收起与窗口不足导致的临时收起分开保存。窗口重新变宽时恢复用户偏好。改变字号、全屏、显示器或窗口尺寸，按当前可用区域布局，不复用离屏的绝对坐标。

图像/视频“适合窗口”状态可以重算适配比例；用户已放大检查局部时应尽量保留查看中心与缩放意图。输入组件达到合理高度上限后内部滚动，不能占满中央。

### 16.2 三个工作对象加一个运行对象

| 对象 | 主要位置与标识 | 禁止的隐式行为 |
|---|---|---|
| 下一次生成配置 | 左侧，明确为下一次请求 | 浏览旧结果时自动覆盖它 |
| 当前查看的结果 | 中央，带实际生成记录/版本 | 用当前默认参数重写其历史来源 |
| 当前选中的素材 | 右侧，区分选中、预览与已采用 | 仅点击素材就替换参考条件或触发推理 |
| 已提交的任务 | 按原会话/模态/项目归属显示 | 模态或模型切换后改变任务输入、取消错误对象 |

“沿用这次设置”“用作首帧”“加入草稿”“删除源素材”都是明确动作，不能由视觉选择状态暗示执行。详情面板应说明当前查看谁。会话标题/历史入口与工作模式切换不同；具体会话列表位置仍待定，不新增第五个永久侧栏。

## 17. 阅读锚点、内容高度与滚动意图

### 17.1 保持正在看的内容，而非只保存一个粗糙坐标

一条消息可能长达多屏。仅保存消息 ID 无法表达消息内部的阅读位置；绝对偏移也会受重排影响。下一阶段的目标是尽量保持同一段可见内容及其相对位置。是否使用渲染器块身份、位置偏移或原生能力，由实际实现决定，不预先要求重写滚动引擎。

| 事件 | 预期行为 |
|---|---|
| 当前跟底，新增内容 | 跟随最新内容，保留真实状态 |
| 用户主动离底，内容继续增长 | 保持阅读位置，提示新内容，不强拉 |
| 前插较早历史 | 当前可见内容不因插入突然跳走 |
| 展开消息编辑/比较区域 | 尽量固定当前操作锚点，新增区域正常占位 |
| 外链确认取消或关闭临时面板 | 不因取消而跳到长气泡中部、开头或底部 |
| 调整边栏、字号、代码换行 | 尽量维持同一段落附近，而非死守旧像素 |
| 会话/分支切换 | 恢复对应对象的阅读状态，拒绝迟到的旧恢复任务 |

普通正文优先共用聊天纵向滚动，不在每个长气泡中再套独立纵向滚动区。代码/宽表格可以局部横向滚动。链接、图片或排版延迟改变高度时，不把它误判为用户要追底。

### 17.2 单一决策责任

位置观测、用户意图和主动跳转应区分。可以观察多个事实，但同一个跳转决定只有明确的负责入口；不要让消息、外层面板与滚动容器各自反复“纠正”彼此。

懒布局中的总高度/偏移可能是估算，验证时需要结合实际可见内容。不要用每帧碰撞检测、不断调用 scrollTo 或增加任意延时补救空间规则。相关原理可参考 [R01]、[R02]；它们不证明 D 当前某个缺陷的根因。

## 18. 悬停、焦点、快捷键与原生编辑

气泡和工具条之间应有连续交互区域。优先用正确命中区域解决悬停断层；必要时再采用短关闭延迟等成熟模式，不默认实现鼠标轨迹预测。点击进入编辑后不再依赖悬停保持。

超长消息需要在当前阅读位置附近找到消息动作或选区动作；不得要求用户滚动几十屏去找底部按钮，也不能让整条工具栏追着鼠标移动。具体形式待原型。

弹出内容打开时有合理初始焦点；关闭时回到原触发点或有效替代位置。触发消息已删除/换分支时，不能聚焦不存在的控件。未保存的人工编辑不因点击空白就静默丢弃；明确放弃才丢弃草稿。

| 输入 | 优先解释规则 |
|---|---|
| Enter | 原生编辑/输入法组字优先，选字不能同时发送 |
| Escape | 当前最内层交互先处理，不能一键同时取消组字、关面板和停模型 |
| 空格 | 文字焦点下输入空格；播放器获得相应上下文时才控制播放 |
| Delete | 文本中删除字符；素材选择上下文下才移除引用，不能误删源文件 |
| Tab/辅助功能 | 能到达与悬停等价的操作，焦点顺序与视觉层级一致 |

视觉设置、消息增量、保存 revision 和切栏动画不应重建原生编辑器。保留 marked text、选区与撤销事务；若切换必须处理组字，用原生编辑边界，不伪造已提交文本。退场组件不得继续接收键盘或发送旧请求。

## 19. 拖放、异步材料与资产生命周期

拖放松手后“接收操作”与“材料准备完成”分开。对已支持的来源，显示导入中/可用/失败，导入未完不假装能送模型。普通文件 URL、原生文件承诺和应用内部资产是不同载荷；超出本阶段支持范围时明确提示，不为原型一次性增加所有来源。

| 落点 | 应有语义 |
|---|---|
| 底部输入组件 | 加入当前请求材料，按能力契约匹配用途 |
| 左侧已标注参考/首帧等槽位 | 绑定明确角色，不靠相同文件类型猜作用 |
| 右侧资产库 | 导入或整理，不自动加入本次生成 |
| 中央结果区 | 需明确定义；默认不能悄悄替换历史结果 |

拖动经过时显示“用作首帧”等用途反馈，不只给一个泛泛加号。批量导入逐项记录成功/失败，不用单条失败抹掉其他合法项。开始操作时冻结接收项目、会话、模型/槽位与采用意图；异步完成不落入随后选中的另一个会话。

聊天正文拖动优先选字，不因气泡视觉悬浮就允许整块随意移动。资产卡片与节点才使用其既定拖动语义。

预览可用不代表原件在线；素材需区分导入中、已准备、失联/离线、被外部修改、保存失败等状态。移除待发引用不删除原件；更改/删除库中原件遵守既有确认、版本和文件操作边界。导出副本、受管理副本和外部引用不混淆。

## 20. 任务、预览与错误恢复

切换工作面不等于改变任务。当前输入组件的停止按钮必须标识所控制对象；另一个模态的任务可在紧凑全局活动入口显示，但不能让文字输入区无说明地停止视频任务。

任务排队、模型准备、运行、取消中、结束与保存失败都使用实际状态。生成结束但保存失败，保留产物并提供重试保存，不默认重推理。取消请求与资源已释放分开；不中断用户的其他未关联工作。

批量结果到达时保持用户当前候选选择，只提示新增；不抢走正在比较的第3张图。视频/音频离开页面是否暂停属于可见的播放策略，不是生成取消；默认播放策略仍待定。

错误就近呈现：字段错误回字段，附件错误回该素材。警告强度与真实风险相称，避免每次普通操作都弹危险确认框。危险源文件操作/外部副作用维持必要确认，可逆的引用移除不等同永久删除。

## 21. 模型能力契约：一份执行事实，多种展示

### 21.1 原则与三个层次

**不能让软件或 UI 成为已批准适配模型能力的瓶颈。**模型支持的能力需要由后端实质适配；后端承诺的用户能力需要有可达 UI。模型不支持的参数不能做成假生效控件；为复用而存在的通用后端分支也不能被误读为该模型承诺。

| 层次 | 内容 | 用途 |
|---|---|---|
| 模型已知能力 | 具体模型/版本/变体在官方实现或可靠材料中的能力 | 适配目标与差距依据，不直接决定按钮一定可用 |
| D 适配器契约 | 当前实现实际接受并消费的输入/参数/组合、返回结果与限制 | 节点、Quick、校验与运行共同依据 |
| 当前请求可用状态 | 权重/组件/素材是否准备，参数是否合法，运行资源是否可用 | 展示补齐办法和当前能否提交，不改写模型本体能力 |

“已经验证到什么范围”另外记录，不把未测等同不支持，也不把类型校验通过等同推理成功。这里的契约是设计概念，可演进现有 Swift 定义；不是要求新增数据库、后台服务或完整 JSON Schema 引擎。

### 21.2 登记粒度与信息

至少能够定位：模型身份/版本/变体、适配器身份/版本、操作路径、契约版本。用户仍看到真实模型名和可读操作名，不被迫阅读技术 ID。

| 描述部分 | 最小语义 |
|---|---|
| 输入 | 稳定字段/端口 ID、类型、用途、数量/顺序、必选或条件必选、兼容组件、文件/媒体限制 |
| 参数 | 类型、单位、默认/未指定含义、硬边界与建议范围、枚举、何时实际生效、来源 |
| 操作 | 真正不同的输入与推理路径；例如某模型确有的新生成/修改，而不是将翻译/改写等提示模板拆成专用后端 |
| 组合规则 | 互斥、至少一个、依赖、区间关系、联合尺寸/时长限制，明确字段级错误 |
| 输出 | 必有/条件输出、数据类型、多个结果、有序或关联关系；不把视频伴随音轨丢掉 |
| 准备与限制 | 需要什么组件、怎样准备、是否当前不适用；事实与资源估算分开 |
| 展示映射 | 区域、分组、控件类型、高级/常用层级、帮助与本地化 key；不另写执行语义 |

同一文件类型不代表同一用途：源音频、风格参考与旋律条件应能区分；多参考图有数量和顺序。不能只声明“audio可选”就把所有控制混成一个槽位。

### 21.3 原生能力、组合能力与软提示分开

参数可来自模型原生接口、配套控制组件、软件前后处理或提示词引导。几种方式都可以合理提供，但要在帮助/请求/来源中说明。

例如固定原生采样率加导出重采样，不等于模型任意采样率生成；重复提交十次，不等于模型内部 batch；在自然语言里要求 BPM 不等于专用节拍硬约束。这些是概念例子，不声明当前某个模型具体支持。

### 21.4 规则实现

简单依赖、互斥和条件可用共享声明表达；涉及素材长度、特定模型限制的复杂校验继续调用已有适配器函数。Quick 与节点使用同一规则，错误定位到输入槽位/参数。运行前仍重新校验，不能以 UI 曾经隐藏字段代替后端检查。

可以借鉴 JSON Schema 的条件语义 [R07]；不为了把所有规则写成 JSON 而创建任意脚本执行器或图灵完备规则系统。

### 21.5 同一能力在节点与 Quick 的表现

| 能力 | 节点 | Quick |
|---|---|---|
| 提示词 | 文字连接/参数 | 底部输入组件 |
| 有序参考图 | 有类型输入及集合 | 可排序、可预览的参考槽位 |
| 参数 | 节点参数或适配接口 | 左侧生成设置 |
| 已支持的源音频区间 | 区间结构/字段 | 中央播放器的区间编辑与数值输入 |
| 已支持的蒙版 | 图像/蒙版输入 | 中央相应编辑工具 |
| 条件/版本错误 | 端口/节点状态 | 相应组件内错误与定位入口 |
| 结果 | 类型化输出端口 | 中央预览＋共享资产记录 |

两者形成语义等价的请求，不要求把整段聊天编译成隐藏图，也不要求布局完全相同。参考角色、歌词与描述有独立后端字段时，不能为了统一输入框而拼成一串再猜着拆。

中央除结果外，可以临时承载当前操作必要的输入编辑；仅在现有模型与适配器确有承诺时提供，不借此增加专业剪辑/音乐工作站。

### 21.6 展示说明与通用/专用控件

数据语义与摆放分离，可参考 JSON Forms 的 UI schema、条件展示及自定义 renderer [R08]。整数、开关、枚举等由通用控件生成；参考素材、歌词、蒙版、区间等复用有相应语义的专用组件。

专用组件仍编辑同一数据，不能私有保存第二份参数或独立重做校验。没有专用布局的普通新参数可先使用通用高级入口防遗漏；复杂核心任务不能永久只给原始 JSON 就算易用。

常用能力直接可达，低频可折叠并提供“全部可调项”；不把后端所有字段无差别堆进一张表单。

### 21.7 隐藏、禁用与缺口说明

| 状态 | 默认工作面 | 能力详情/处理方式 |
|---|---|---|
| 模型确实不支持 | 不出现假可用参数 | 需要比较或查询时说明不支持 |
| 模型支持、D未适配 | 不提供假执行入口 | 标为D适配缺口，不改写成模型不支持 |
| 已适配、组件未准备 | 可发现能力及准备动作 | 说明缺什么，不能只给无解释灰按钮 |
| 当前操作不适用 | 收起或说明未采用 | 保留操作草稿但不静默发送旧值 |
| 当前输入不合法 | 控件仍可修正 | 定位缺项/冲突，重新校验 |
| 已实现但未实测 | 与可用性分列 | 准确证据范围，不假通过、不永久禁用合法高配路径 |

全部未支持能力不在工作面铺一片灰色；完整解释归模型详情。已批准能力的“尚未适配”标签不能代替完成它。

### 21.8 模型切换、版本与不丢用户数据

- 只有语义、单位和规则明确兼容的字段才能迁移；同名 `strength` 不自动视为相同意义。
- 按模型/操作保存有效配置与未完成编辑；切回可恢复，不用一次模型切换擦掉用户输入。
- 不兼容参考材料保留，标为当前未采用，要求用户选择；不能静默删掉、缩减或只传第一项。
- 隐藏字段可留在编辑草稿中，但本次有效请求仅带适用值。旧的隐藏非默认值不应继续偷偷生效。
- 建议范围不是硬约束；真实模型/后端限制与资源风险分开，不以开发机配置永久封死其他用户能力。
- 当前已提交请求冻结身份、版本、输入和参数。升级/切换只影响未来请求；旧结果按其真实记录显示。
- 更新展示结构由模型/操作/契约及相关准备状态变化触发，不因每次按键重建注册表、校验全库或重建编辑器。

### 21.9 与现有 D 架构衔接及防遗漏

本轮针对性源码核对（67ac49f3）确认已有 WorkflowOperationDefinition、WorkflowPortDefinition、WorkflowRegistry 与 Quick 根据 definition 生成输入/参数。应优先扩展现有契约，不另外建立 Quick 专用支持表。现有字段名过滤（例如 task/promptText 与“大部分其余字段进高级”）可在下一阶段改为语义展示映射。

面向用户的能力页和面向开发的覆盖表尽量从同一描述导出。上游资料仍需人工可靠核对，不能从函数签名推导“所有功能已支持”。覆盖关系为：

**上游已知能力 → D适配器实际消费 → 节点入口 → Quick入口 → 验证范围。**

结构检查可以验证字段可达、参数进入请求、隐藏值不生效、两入口校验一致；真实推理只覆盖新的执行语义或独立风险，不为排版修改重跑全部模型。能力表首先用于查漏和展示，不新建运行监控服务。

## 23. 仍需原型决定的细节（不自动扩为实现任务）

第12节未定事项继续保留，新增需讨论：

1. 同时有多个任务时，全局活动入口的具体位置及与当前输入停止按钮的关系。
2. 会话导航、右侧预览对象和下一次参数之间如何最清楚地标识；列表是否可固定展开。
3. 极长消息中整条消息动作与选区动作的具体可达形式。
4. 模型拥有多种实际操作时的选择器形式；哪些字段用专用组件，哪些先通用呈现。
5. 模型切换的兼容设置继承提示、未采用素材区与回退方式。
6. 视频/音频离开工作面后的播放策略；是否允许并行试听与播放来源标识。
7. 更细的阅读锚点用何种原生/渲染器能力保存，及其持久化范围。不给旧收口凭空追加“全文定位引擎”门槛。

## 24. 下一阶段代表原型与差异回归

| 场景 | 要验证的设计，而非新模型能力 |
|---|---|
| 长回答读到中间，开关边栏与链接确认 | 阅读锚点稳定，整条/选区操作可达 |
| 拼音未选字时收到输出或移动面板 | 组字、焦点、Undo与发送优先级正确 |
| 混合文件导入中有一项失败，切会话 | 逐项状态、归属与来源保护 |
| 视频运行中切文字，并查看旧视频 | 当前配置、旧结果、在途任务不混淆 |
| 切到不支持现有参考的模型 | 数据保留，未采用清楚，后端不收隐藏旧值 |
| 同一音频模态内换不同能力模型 | 字段/角色/规则真实变化，骨架不变，不出现无效滑杆 |
| 窄窗口、大字号、低动效和高对比度 | 核心操作可达，正文可读，命中位置一致 |
| 批量结果持续到达、其中一份保存失败 | 不抢当前选择；重试保存不重生成 |

复用既有内容、可控任务与数据；不为每个视觉状态运行大模型。UI重排后对受影响的输入、滚动、菜单、拖放与资产交接回归，不无差别重复全部推理和备份检查。

## 25. 合并后的设计目标与来源边界

**统一空间骨架；按实际能力装配组件；用同一契约连接模型、后端、节点和 Quick；让状态、对象、来源与错误始终清楚。**
