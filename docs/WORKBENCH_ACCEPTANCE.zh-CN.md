# 图像项目工作台验收（D-W01）

日期：2026-09-07。设备：Apple M4／16 GiB，macOS 26.6.2，Xcode 26.6；项目、模型、构建与证据均优先使用外置 SSD。

本检查点将原来的界面原型替换为可以实际生成、保存、导出和恢复图片的项目工作台。它是可靠出图 Alpha 的第一个产品检查点；模型安装器尚未实现，目前需要选择已安装的固定 FLUX.2 Klein 4B q8 模型。

## 已实现的用户流程

- 单个主窗口打开一个 `.dproject` 自包含项目。左侧作品、中央画布、右侧创作参数，下方可折叠任务记录。
- 原生 SwiftUI 分栏、工具栏、检查器；生成与浮动缩放控制使用 Apple Liquid Glass。图片背景保持不透明，避免材质干扰作品观察。提供减少透明度／动态效果分支。
- 本地模型登记与重新授权，实际推理前仍校验完整固定权重；没有下载、其他模型或占位模态按钮。
- 提示词、随机／固定 seed；固定 0 是有效输入。当前执行规格明确为 512×512、4 步、guidance 1。
- 请求提交前保存并冻结；应用按提交顺序交给同一个 DRuntime，实时显示准备、生成、取消、释放和保存阶段。
- 作品登记成功才显示完成；PNG 原字节导出，不静默覆盖已有文件。图片支持适合窗口、真实像素 100% 和平移。
- 作品、任务、生成条件和未提交草稿保存到项目；重新打开不自动运行中断任务。模型权重与安全作用域书签保存在项目之外。
- 打开中的项目被移动后，可以重新选择同一个目录；文件身份确认后迁移会话与锁，并重定位尚未登记的结果。不会把具有相同清单 ID 的另一份复制品当作原目录。

## 保留与替换的边界

DInference／DRuntime 的生产源码未改。DMLXBackend 的图像计算与数值转换未改，只修正两处文件系统祖先遍历以适配真实 App Sandbox。具体问题、失败对照与修复见 [目录访问说明](research/SANDBOX_DIRECTORY_ACCESS.zh-CN.md)。

`Packages/UI` 继续作为已有工作台包，按 Project、Services、State、Views 组织，只依赖 DInference。D 应用负责装配 DRuntime 和 DMLXBackend。旧生成视图与旧 ViewModel 已退出应用；其他旧功能包留在仓库中供后续取舍，不再成为新应用的依赖。没有新增独立框架库，也没有修改 vendor。

项目文件包含 schemaVersion、递增 revision、资产身份、角色、相对路径、可确认的媒体元数据和生成来源。原始媒体可以没有推理任务归属，未知位深／色彩空间保持未知；当前解码和登记仍仅实现 PNG。RAW、DNG、TIFF、OpenEXR 及专业音视频是已接受的后续目标，详见 [目标清单](PRODUCT_GOALS.zh-CN.md)。

## 当前限制与下一步

- 这是开发构建，不是已签名公证的发行商品。应用最低系统版本保持为 macOS 26.2。
- 当前只支持已验证的本地图像模型与固定规格。模型安装／下载管理是下一检查点；旧下载器不重新接入。
- PNG 登记读取上限 64 MiB，项目清单上限 32 MiB；过大文件明确拒绝，不截断保存。未来高位深媒体需要重新设计相应读取与预览预算。
- 发布后中断可以恢复图片，但缺失的完整执行结果不能被伪造为成功；恢复记录会明确说明。移动目录后旧实例无法安全确认的临时文件保留，不猜测删除。
- 当前实看采用系统深色界面。浅色、减少透明度、Reduce Motion 和更全面可访问性的实现已接入系统，但尚未做完整的人工兼容矩阵验收。
- 本轮没有重新进行全量 GPU 内存压力测试；资源计算部分沿用 B2 实现和 [B2 证据](IMAGE_RUNTIME_ACCEPTANCE.zh-CN.md)，不能把本轮构建或 PNG 一致性解释为新的长期无泄漏证明。

下一步先细化模型安装与管理，补齐“没有模型 → 安装 → 生成 → 自动保存 → 重新打开”的 Alpha 流程。新目标通过目标清单追加；RAW 等低优先级适配不会自动扩大当前检查点。

## 复验入口

`./scripts/test-workbench.sh` 验证项目／应用服务；`./scripts/test-foundation.sh` 验证核心；`./scripts/build-local.sh` 构建正常沙盒应用。测试与报告路径以仓库脚本和机器证据为准。

应用托管 XCTest 会临时修改测试宿主签名，测试后应再次正常构建再进行权限验收。任何 UI 自动化启动失败都要保留原始失败结果，不能通过扩大应用访问权限来隐藏。
