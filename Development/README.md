# Local development resources

Debug uses `Development.local.xcconfig` (ignored) to locate the verified local engine resource set and the already approved development signing identity. Prepare once using `scripts/prepare-development-resources.py`, then set `D_DEVELOPMENT_RESOURCES` to that absolute output directory. Set `D_DEVELOPMENT_SIGNING_IDENTITY` and `D_DEVELOPMENT_TEAM` only to your existing development identity. Do not put credentials in this file.

The normal D build validates the inventory, uses the native Xcode Resources copy phase, and then performs the ordinary Xcode signing step. Script sandboxing remains enabled; the validator writes no engine files. The resource set contains runtime code and, for the current internal Pitch engine, the explicitly tracked evaluation weight; it does not contain Qwen/FLUX/MRT2/Wan weights. This is a development configuration, not a distribution artifact. Missing or changed resource inputs fail with a preparation message rather than producing an app that appears ready.

No dependencies are downloaded or installed during a build. Xcode owns and may replace the Engines directory in its current build output. Resource sources, model weights and other installed applications remain read-only; use an independent task-owned DerivedData directory.

For this node-language trial, choose the shared **D Nodes** scheme and **My Mac**. It runs the same Debug D target with a fixed `D_UI_TEST_SESSION` value, isolating the model index and preferences from ordinary D while preserving the trial across launches. It does not bypass project access or model consent. An explicit shared **D** scheme preserves the ordinary build/test entry after adding the trial scheme suppressed Xcode's automatically generated entry; it uses the existing targets and does not change the signing identity. See `docs/NODE_LANGUAGE_TRY.zh-CN.md` for the delivery status; a successful build is not an observed Xcode Run.
